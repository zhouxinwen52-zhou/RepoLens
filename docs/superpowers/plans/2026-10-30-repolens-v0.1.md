# RepoLens V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Approved for execution  
**Last updated:** 2026-11-10
**Execution method:** Native, one day at a time in a fresh session  
**Approval protocol:** Root `AGENTS.md` requires a separate human review gate after every checkbox step.  

**Goal:** Build an installable, profile-aware Codex plugin that routes unfamiliar repositories into learning or usage workflows, produces evidence-backed learning reports with Archify diagrams, and evaluates project ideas with a stable rubric.

**Architecture:** The product is primarily a portable Codex plugin made of Markdown skills, reference documents, templates, and a root manifest. A small TypeScript/Node helper layer owns only deterministic work: Profile validation, safe repository acquisition, contract validation, Archify model adaptation, and eval orchestration. Model judgment stays in the skills, while schemas and tests enforce stable boundaries and prevent unsupported output.

**Tech Stack:** Markdown, JSON, YAML, TypeScript, Node.js 20+, Zod, Vitest, Git, optional GitHub CLI/plugin, and the external Archify skill.

**Spec:** `docs/superpowers/specs/2026-10-30-repolens-v0.1-design.md`

**Artifact-first addendum:** `docs/superpowers/specs/2026-11-10-artifact-first-learning-report-design.md`

**PRD:** `docs/product/prd.md`

**Traceability:** `docs/product/requirements-traceability.md`

## Global Constraints

- Formal acceptance environment: Codex desktop on macOS; Codex CLI is best effort.
- Explicit fixture coverage: TypeScript, Python, and Java repositories; other languages are best effort and disclosed as such.
- Plugin source of truth: root `plugin.json`; add `.codex-plugin/plugin.json` only after a verified compatibility requirement.
- V0.1 skills: `setup-profile`, `learn-project`, and `evaluate-idea`.
- No custom MCP server, hooks, custom UI, repository discovery, automatic third-party installation, or execution of analyzed repository code.
- Existing local repositories are read-only and never cleaned or deleted.
- URL repositories use `git clone --depth 1` in an OS temporary directory and are deleted after success or failure unless `keep_repo` is explicitly requested.
- Repository contents are untrusted; sensitive-file contents are never opened.
- Archify is required for a complete Learning Workflow; without it, output is explicitly degraded and incomplete.
- Model output must cite evidence, distinguish `Observed` from `Inferred`, and expose uncertainty instead of inventing missing facts.
- Tests assert schemas and semantic properties, never exact generated prose.
- Normal plugin users never provide an OpenAI API key; only the developer-only `npm run eval:model` command reads `OPENAI_API_KEY` from the environment.
- Model evals use one configurable low-cost API model over the five local fixtures; TypeScript checks expected properties without a second model grader.
- Learning Reports and validated diagram HTML files are durable user-local artifacts; analyzed repositories remain unchanged unless the user explicitly chooses an artifact destination.
- The complete Learning Report is artifact-first: `report.md` contains the detailed stages and evidence index, while the conversation defaults to progress plus a concise handoff rather than duplicating the report.
- A failed Learning Report save retains the validated structured result only within the current run and offers retry-save; V0.1 adds no cross-conversation failure cache.
- External idea research requires explicit per-evaluation consent; declining research continues locally with affected evidence marked `Unknown`.
- The installed plugin emits no telemetry and sends no Profile or report data to a RepoLens-operated service.
- Use TDD for deterministic TypeScript behavior and commit after each independently testable task.

## Review Focus

- An untrusted repository must not leak embedded credentials, expose sensitive/version-control contents, delete a local checkout, or receive generated artifacts by default; Tasks 3, 4, and 7 pin these boundaries.
- A diagram element or runtime step without a valid evidence reference must fail validation rather than appear in a successful report; Task 6 pins evidence integrity.
- A Profile opt-out or absence of a defensible `New` concept must produce `Skipped by Profile` or `Reinforcement`, not a failed stage or invented novelty; Task 7 pins these states.
- Idea content must not leave the local context without consent, and `BUILD` must not survive a decision-changing Unknown; Task 8 pins these rules.
- Artifact or Archify failure must preserve the valid structured result while remaining visibly incomplete; Learning Report save failure offers current-run retry without dumping the full report into the conversation or claiming cross-run recovery. Tasks 6, 7, and 10 pin recovery.
